# 总结管线说明

本文描述当前代码实际执行的文字稿与总结稿处理路径，供维护和排错使用。用户最终只会在结果目录中得到 `完整文字稿.md` 和 `总结.md`。

## 处理流程

```text
Whisper SRT 分段
  → 带起止时间的自然段
  → 音量与语速相对值
  → 主题识别与篇幅规划
  → 分主题初稿
  → 阿拉伯数字硬校正
  → 事实质询与修正
  → 阿拉伯数字硬校正
  → 逻辑质询与修正
  → 阿拉伯数字硬校正
  → 确定性质询与修正
  → 阿拉伯数字硬校正
  → 只读终审
  → 正文与文末风险提示
```

转写阶段让 `whisper.cpp` 输出 SRT，随后把相邻字幕合成带时间范围的自然段。应用从本地 WAV 计算每段相对于全文中位数的音量和语速；这些值只帮助主题规划与篇幅分配，不会被写成课程事实。

总结阶段先识别主题，将报名、优惠和操作提醒归为通知，将没有分析价值的歌词或噪声排除。每个主题按对应原文分块生成初稿，因此后续审核和数字校正始终使用同一块原文，不跨主题寻找证据。

## 三轮质询与修正

每个主题块固定执行三轮反方质询，每轮只找一个最可能改变读者理解的问题：

1. 事实轮核对人物、对象、事件和行为。
2. 逻辑轮核对因果、条件、范围、观点混合和自行添加的动机。
3. 确定性轮核对猜测、希望、听说、不知道、比喻、主观判断和否定。

作者模型每轮根据原文回应质疑：质疑成立就保守修改或删除，原文确有支持则可保留。修订守卫会拒绝空稿、篇幅异常漂移、突然退回第一人称直播口语或大段照抄原文的版本。前三轮结束后还有一次只读终审，不再改正文。

## 数字硬校正

程序提取总结中的阿拉伯数字，并按去除千位逗号、统一半角百分号后的值，与当前主题块原文逐项比较。时间标签由程序生成，不参与这项检查。

发现原文没有的数字时，数字校对模型必须直接替换为原文值；无法确定正确值时删除该数字化断言。每次初稿和每轮语义修订后都会重新检查，最多连续校正两次。数字问题不会让整篇总结失败或触发提取式摘要；自动校正后仍无法消除的数字会保留最终正文，并进入文末风险提示。

中文数字和不含阿拉伯数字的数量表达由三轮语义审核负责，不属于这项字符串硬校正。

## 风险提示

语义质疑只有同时满足以下条件才会进入 `总结.md` 文末的 `审核风险提示`：

- 在三轮质询与只读终审中至少出现两次相近质疑；
- 被质疑的陈述在最终正文中仍然存在。

风险项集中列出主题、争议陈述、理由和对应逐字稿时间范围，便于回看视频。若审核模型没有给出有效段落编号，时间范围会退回该主题块覆盖的全部原文。自动校正后仍未通过的数字硬校验也会单独列为风险。

## 维护入口与验证

- `src/main/services/transcription-service.cjs`：SRT 转写与带时间段落组装。
- `src/main/services/audio-emphasis.cjs`：本地 WAV 音量和语速分析。
- `src/main/services/summarization-service.cjs`：主题规划、初稿、数字校正、三轮质询、终审和风险附录。
- `src/main/job-controller.cjs`：任务进度和最终文件写入。
- `test/transcript-utils.test.cjs`、`test/audio-emphasis.test.cjs`、`test/summarization-service.test.cjs`：主要回归测试。

提交改动前运行：

```powershell
npm run check
npm test
```

涉及提示词或风险判定的改动，除单元测试外还应使用带明确事实、因果、否定、推测和数字的脱敏短样本进行本地模型验证。不要把真实课程内容加入仓库或测试夹具。
